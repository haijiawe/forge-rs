# 删除与改名台账

这份文件存在的理由很具体：**这个仓库的 git 历史里一个删除提交都没有**
（`git log --diff-filter=D` 命中 0），因为被删掉的东西本来就不在这个仓库里。
所以「某个文件是被删了，还是从没存在过」这个问题，代码和 `git log` 都答不了。

答案在这里。每一条都写日期、删了什么、为什么、东西去哪了、原始记录在哪。

| 为什么 | 用户要求换 Rust 技术栈；继续维护两棵树会让每一个行为有两个实现、两套测试、两个真相 |

| 留下的痕迹 | 一些注释和契约里的 `forge-go/...`、`internal/...`、`cmd/forge` 路径指向那棵已不存在的树。这是刻意的：它们标注的是「这条规则的来源」，不是「去这里找文件」。`scripts/check-links.cjs` 要求这些路径**在同一行**带上「已退役的 Go 树」之类限定词，否则报错 |

> 影响：`docs/01` 到 `docs/07` 这七个编号**从来没有进入过本仓库**。`ls docs` 从
> `08-rust-port.md` 开始不是漏文件。编号刻意不压缩，因为 crate README、契约和提交
> 信息里已经有指向 08 以后编号的引用，重排会让它们全部指错。

| 何时 | 从 | 到 | 波及 |

| 2026-11-21 | `forge` | `hearth` | 24 个 crate 名、`hearth_*` 模块、`HEARTH_*` 环境变量、`~/.hearth`、WebSocket 子协议 `hearth.v1`、协议头 `X-Hearth-Protocol`、`bin/hearth.exe`、仓库名 `haijiawe/forge-rs` → `haijiawe/hearth` |

改名时**刻意保留**了两处旧名，因为改掉会让它们指向不存在的东西：

- 契约与注释里的 `forge-go/...`、`cmd/forge`——它们是已删 Go 树里的真实路径，是规则的出处。
- market 测试语料里那个夹具 tarball 的内部字符串——它是二进制，摘要被钉死在索引里（`fc52df77…`），改内容等于换语料。

## 怎么维护这份文件

删除或改名之后**手动加一条**。没有工具能替你生成：被删的东西已经不在树上，
任何「扫一遍仓库」的脚本都看不见它——这正是这份文件存在的全部原因。

一条合格的记录要能回答四个问题：**删了什么、为什么、现在用什么、原始记录在哪。**
如果第四项是「不在了」，就明写不在了；写「见 git 历史」而历史里没有，比空着更坏。
